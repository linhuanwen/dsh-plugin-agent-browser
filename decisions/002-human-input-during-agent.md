# D12 Agent 操作期间要不要"禁止人工输入"

> 来源：2026-11-20 用户提问——"我看了下 kimi code 里面的浏览器插件使用，在 agent 操作的时候，人工最好不要介入，所以在 agent 操作的时候，禁止了人工操作的输入有效性，你觉得这一点是否有必要做？"
> 状态：`暂缓`——2026-11-20 用户决定"这个暂时先不做了"。下面保留完整论证与落地要求，将来要做时直接照着开工，不用重新论证。

---

## 问题

Agent 正在驱动侧栏页面时，用户直接在面板里点/敲——这批输入该**禁止**、**忽略**、还是**检测后让位**？

## 选项

| 代号 | 做法 | 结论 |
|---|---|---|
| A | 硬禁：盖一层拦截层，agent 相位下人工输入一律无效，只剩「接管」按钮可用（Kimi 做法） | ⚠️ **降级为可选开关**，不做默认 |
| B | 现状：相位机只管 agent→taken_over 的**工具侧**拒绝，人工在面板里怎么点都没人知道 | ❌ 否决（埋雷） |
| C | 检测 + 抢占：页面内监听真实人工输入 → 立即转 `taken_over` + 清队列，agent 动作返回结构化错误 | ✅ **选中（默认行为）** |
| D | C + 动作前 ref 新鲜度校验（stale-ref 拒绝） | ✅ **选中（与 C 一起做）** |

## 选中

**默认 C+D，A 降级成用户主动开启的「锁定面板」开关（默认关）。**

## 理由

**1. 单写者原则成立，但"禁输入"是错的手术刀。**
真问题是"人改过页面之后 agent 还按旧认知动手"，不是"两个指针在同一毫秒相撞"。禁输入只挡后者，且代价很大：拦截层必须**和相位机严格同步**——`needs_human` 时要自动撤掉（否则用户过不了验证码），`taken_over` 时要撤掉（否则接管按钮点不动）。同步一旦漏一拍，用户面对的就是"点了没反应、也没有任何提示"，这比原来那个问题更难查。

**2. 技术上也比看上去贵。** host 侧盖一层只能挡鼠标；webview 拿到焦点后键盘事件直接进 guest，host 根本收不到。要真拦键盘，只能在 `plugin/inject/*.js` 里 `preventDefault()`——等于把"禁输入"做成页面内注入，和他们的验证检测/接管注入同层，权限面更大。

**3. 现有相位机其实已经做了 2/3，缺的只有一处。**

| 已有行为 | 位置 |
|---|---|
| `taken_over` 下所有写类工具（`open/click/type/press/eval`）直接拒 | `plugin/bridge.js:160` |
| `needs_human` 下除 `open` 外全部拒（读仍可用） | `plugin/bridge.js:166` |
| 进入 `taken_over` 时清空队列并 fail 掉在途命令 | `plugin/bridge.js:142` |
| 用户点「我来接管」上报相位 | `plugin/client.js:1150` |

唯一的真空是：**`phase === 'agent'` 期间，人在面板里点了什么、敲了什么，插件完全不知道**（`plugin/inject/` 里没有任何 `pointerdown`/`keydown` 监听，徽章照旧显示「Agent 正在操作」）。补上这一处，B 的问题就没了。

**4. 顺序上，stale-ref 比抢占更值钱。**
页面本来就可能自己变（轮播、懒加载、广告浮层、地图瓦片重排），禁输入挡不住这些；只有"动作前校验 ref 指向的还是不是同一个节点"能挡住"点错东西"。所以 D 必须做，而且优先级高于 C。

**5. Kimi 的场景和这里不一样，不该照抄。**
Kimi 是"云端浏览器 + 人旁观"，人是观众，禁输入几乎无成本；这里是"人和 agent 同看一个面板"，`keepMounted`、两轮人工接管都是刻意设计的产品卖点，人是**在场者**。把在场者锁在门外，等于否掉自己的差异点。

**6. 对不可逆动作，正确手段是分级确认，不是锁面板。**
提交订单、支付、发消息这类，应该在工具层给动作打级（`safe` / `confirm`），而不是靠"人不能碰"来保证安全。

## 被否决项

- **A 作为默认**：见理由 1、2、5。保留为显式开关，是因为无人值守批处理场景确实需要它。
- **B 保持现状**：`taken_over` 只由用户**主动点按钮**触发，人随手点一下页面不算接管——agent 随后按失效 ref 动手，事故无据可查。

## 落地要求（可写进 V8 家族的验收口径）

1. **抢占信号**：`plugin/inject/` 里 capture 阶段监听 `pointerdown` / `keydown`，`event.isTrusted === true` 且当前相位为 `agent` 时上报 `user_interrupt { x, y, target, digest }`；主进程收到后转 `taken_over` + `#flushSession`。
2. **可读的让位错误**：agent 下一个动作返回 `taken_over: 页面在你上次快照后被人工修改过，请重新快照后再操作。`（附 digest 变化），不要笼统失败。
3. **stale-ref 校验**：快照时记录 `{ nodeId, tagName, textPrefix(≤40), rectHash }`；`click` / `type` 前重算，不一致返回 `stale_ref: 目标已变化，请重新 snapshot`，**绝不点空**。
4. **可选锁定开关**：`lockPanel: false` 默认关；开启时拦截层吞掉鼠标与键盘（键盘走 inject），中央提示「已锁定 · 点此接管」，`needs_human` / `taken_over` 自动解锁。
5. **徽章不撒谎**：相位为 `agent` 但检测到人工输入后，徽章必须在 **≤1 s** 内切换成「已接管」，不能等下一次工具调用。

## 一句话

**不要禁止人动手，要让人一动手 agent 立刻让位，并保证 agent 从不让位给"过期的页面认知"。**
