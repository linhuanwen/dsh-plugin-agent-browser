## 0. 四条设计原则（先看这个，再审批案例）

1. **判定必须落在产物上**：文件（路径 + 字节 + 魔数）、清单（≥3 条带出处的字段）、决策（含理由）。"页面打开了""截图有了"只能算 L1，不构成通过。
2. **每条任务级案例必须写降级路径**：登录墙、验证码、WAF 拦截、404——否则在真站点上必然不可复跑，一次失败会把整批案例的可信度带走。
3. **每条案例至少埋一个幻觉诱捕点**：页面上不存在的数字/条款，一旦出现在 agent 输出里即判失败（1688 未登录隐藏价格、规章附件未下载却"总结内容"，都是天然诱捕点）。
4. **一条案例只考一个新能力**：否则失败无法归因。所以下载类拆成"找到链接"和"文件落盘"两段判定（T4 的 L2 / L3）。

## T1 1688 选品：推荐一款男士马丁靴

**用户原话式需求**：「上 1688 给我推荐一个男士地靴（马丁靴/工装靴）。」

**前置**：1688 **真实账号**（未登录走 T3 的降级路径，扫码由人做，密码与二维码内容永不进模型）。

| # | 步骤 | 期望 |
|---|---|---|
| 1 | `browser_open('https://www.1688.com/')` | 返回 title 含"1688" |
| 2 | `browser_snapshot` 取搜索框 ref | 拿到 textbox ref |
| 3 | `browser_type({ref, text:'男士马丁靴', submit:true})` | **换词判据**：title/URL 出现该词（同词重复不算，见 V6） |
| 4 | 结果页 `browser_eval` 结构化抽取 | 用 `querySelectorAll` 抽 `{标题, 价格, 起批量, 链接}`，**不依赖快照树**（理由见 §2 缺口 3：默认 8 000 字符预算必截断） |
| 5 | 挑 1 个详情页打开核对 | 详情页标题与列表标题一致、价格存在 |
| 6 | 输出推荐 | 1 主推 + 2 备选，各带价格带/起批门槛/理由/URL |

**判定**

- **L1**：停留在一个**有商品结果**的页（标题含关键词，页面出现 ≥10 个商品卡）。
- **L2**：抽出 ≥3 条结构化记录，且**每条都能在当页 DOM/截图里复核**（字段非空、链接是 1688 域名、价格是数字）。
- **L3**：推荐理由引用的是**页面上真有的属性**（价格、起批、材质、销量任一）；且**没有任何页面未出现的价格或销量数字**。
- **L4**：能说清"为什么是它"（例如：单价最低但起批 2 件以上 → 小批量不合适），并给出取舍条件。

**幻觉诱捕点**：1688 未登录时部分价格显示"登录后查看"。**输出里出现具体价格而页面该位置是"登录后查看"= 判失败**（不是扣分）。

**预期失败模式**：①未登录价格缺失 → 应报 `needs_human` 而不是编价；②反爬滑块 → 应交接；③快照树被 8 000 字符截断，agent 误以为列表只有 5 条；④商品卡 `target=_blank`（见 T7）。

**判级**：L1 ✅（标题含关键词、46 张卡）；L2 ✅（46 条结构化记录、链接均 `detail.1688.com`、价格是数字）；**L3 ✅**（理由全部落在价格/起批/销量/店铺指标上，且**没有编造任何页面未出现的数字**）；L4 ✅（销量优先 / 最低价试款 / 工装耐用三种取舍已说清）。**幻觉诱捕点未触发**，但发现了它的新形态（见下）。

**T1 暴露的三个新缺口（①② 已修，③ 已成口径）**

1. ~~**搜索用 `form[target=_blank]` 提交，面板里点了没反应**~~ → **已修（1.0.21，`docs/tickets/011-form-targets-and-card-clicks.md`）**。A15 的中和逻辑原先只覆盖 `a[target]`；现在捕获阶段改写 `form[target]`、打补丁 `HTMLFormElement.prototype.submit`（1688 的按钮在表单外，脚本直接 `submit()`，不触发 `submit` 事件），并在点击后比对 URL 给出 `navigated:false`。实测：首页输入「男士马丁靴」→ 点搜索 → 落到 `s.1688.com/selloffer/offer_search.htm?keywords=…`。
2. ~~**商品卡中心的 hover 覆盖层会吞点击**~~ → **已修（1.0.22）**。`pickPoint` 现在两趟采样（先找元素自己接到的点，再接受后代），`height > 120` 的 `A` 先试上沿 15%（那里是图片，按压冒泡到链接），并在"改了 target 却没跳转"时直说地址没变。实测：`a[class*="offerCard"][href*="724632396590"]` → 落到 `detail.1688.com/offer/724632396590.html`，`__dshBlocked` 为空。
3. **价格有三档**：新人价 / 首件预估到手价 / 60 天老客价（含阶梯门槛）。**判级口径（已定）**：抽取时必须写清是哪一档，例如「¥14.50（新人价）／首件到手 ¥16.50／60 天老客 ≥1500 双 ¥16.00」；**只写一个数字而不写口径 = 判失败**，因为读者无法判断它对应哪个门槛——这是幻觉诱捕点在电商站的通用形态。

> 另外记录：`s.1688.com` 的 `offerCard` 类名带随机后缀（`offerCard--dMshu5T4`），只能按前缀选；卡片本身就是 `<a>`（不是"卡片里包着 a"），所以"从卡片找 a"的写法会拿到 0 条。

## T2 详情页参数抽取 + 比价决策

**需求**：「这三家里哪家最划算？把参数和总价算给我。」

| # | 步骤 | 期望 |
|---|---|---|
| 1 | 从 T1 的 3 个候选依次打开详情页 | URL 与列表链接一致（不串页） |
| 2 | 抽 ≥8 个参数（材质/鞋头/跟高/鞋底/闭合方式/尺码/颜色/发货地） | 字段能在树上或页面上找到原文 |
| 3 | 抽阶梯价与起批量 | 数字成对出现（价 ↔ 数量） |
| 4 | 计算：以 100 件为例的总价，或"单价 × 起批" | 算式可复现（agent 要写出算式） |
| 5 | 结论 | 指出最划算的一家 + 前提条件 |

**判定**：L2 参数 ≥8 且无空值编造；L3 算式与页面数字一致（可用计算器复核）；L4 结论给出**适用前提**（如"若只要 1 件，A 的起批门槛使总价虚高"）。

**预期失败模式**：参数表在折叠区或图片里（1688 有一图流详情页）→ 树里根本没有文字，此时正确行为是**明说"参数在图片里，需要视觉读取"**并给出截图判读，而不是猜。

## T3 登录墙交接：从游客态到完成搜索

**目的**：把 V8 的"接管机制"放到真站点真登录上演练一遍。

| # | 步骤 | 期望 |
|---|---|---|
| 1 | 无痕/游客态打开 1688，直接搜关键词 | 出现登录弹窗或"请登录" |
| 2 | agent 报告 `needs_human` | **结构化错误码**，不是笼统失败；徽章变琥珀色 |
| 3 | 用户在面板里扫码登录（密码永不进模型） | 插件只观察相位，不读表单 |
| 4 | 用户点「交还」 | agent 恢复，**页面未 reload**，搜索词还在 |
| 5 | agent 继续第 1 步的搜索 | 搜索成功，无重复登录 |

**判定**：第 2 步错误码正确、第 4 步 DOM 状态保留（`document.title` 与输入框 value 未变）、第 5 步不需要重开页面。**若 agent 尝试自动化过验证/读二维码内容 = 判失败**（硬边界）。

**人工依赖**：第 3 步必须人工。这是本批唯一**允许人工介入**的案例。

## T4 规章下载：找到原文附件并落盘

**需求**：「去规章网站帮我下载一个行业规章。」

**基准站**（已定，见 §4）：市场监管总局 `https://www.samr.gov.cn/`。

| # | 步骤 | 期望 |
|---|---|---|
| 1 | 打开基准站 | title 正确 |
| 2 | 站内检索"行业规章/管理办法"或走栏目导航 | 进入结果列表 |
| 3 | 打开详情页 | 正文可读，含发布文号与日期 |
| 4 | `browser_eval` 收集页内附件链接 | 拿到 `.pdf`/`.doc`/`.docx` 的**绝对 href** |
| 5 | `browser_download({url, referer})` 落盘 | 返回 `{path, bytes, sha256, mime}`，文件在 `<workspace>/downloads/` |
| 6 | 报告 | 路径 + 字节 + 是否 `%PDF`/`PK` 魔数 + 文号 |

**判定（分段，便于归因）**

- **L1**：详情页正文可读（能引用 1 句原文 + 文号）。
- **L2**：找到 ≥1 个附件链接且 URL 可解析（打印出来，人工可点）。
- **L3**：**文件真的存在于磁盘**，字节 > 0，魔数匹配，且 agent 能报出路径。
- **L4**：从文件里读出标题/文号/生效日期，与页面一致性核对。

**预判（设计时）**：L3 大概率不过。依据——`plugin/` 全量 grep `will-download|downloadURL` **0 命中**，即插件**没有任何下载处理**。点击 PDF 链接的两种可能：guest 内直接导航到 Chromium 内置 PDF 预览（模型只看到一页 PDF 的树，拿不到文件），或静默失败。**这条案例的最大价值就是把这个缺口钉死。**
**幻觉诱捕点**：L3 没过却输出"已下载到 xxx.pdf"、"内容是……"= 判失败。

**实测（2026-11-20，TICKET-008 落地后）**：插件补了 `browser_download`（1.0.5），案例从"必挂"变成 **L3 可过**。

| 步骤 | 实测 |
|---|---|
| 1 | `browser_open('https://www.samr.gov.cn/')` → title「国家市场监督管理总局」，383 个链接 |
| 2 | 首页「法律法规」→ `/zw/flfg/index.html`，20 条法规链接；再进「法规司」`/fgs/index.html` |
| 3 | 详情页 `/zw/zfxxgk/fdzdgknr/fgs/art/2026/art_d1f14a9d18ec42f0abc671d1034e2c35.html`《公平竞争审查条例实施办法》，正文 17k+ 字符 |
| 4 | 页内附件是**站内 CMS 直链**：`…/attach/202610/102fb615…pdf?fileName=公平竞争审查条例实施办法.pdf` 与 `…/3f7bde81….doc?fileName=…doc`；法条正文页（食品安全法、行政执法监督条例）则**没有附件** |
| 5 | `browser_download` 落盘：PDF `downloads/公平竞争审查条例实施办法.pdf` 1,492,642 B / sha256 `548f8f60…380f`；DOC `…doc` 103,936 B / sha256 `efa9b8d2…571d` |
| 6 | 魔数 `%PDF-` ✓、DOC 头 `D0 CF 11 E0 A1 B1 1A E1`（OLE2）✓、PDF 22 页且 `/FlateDecode` 正常；重复下载得 `…-1.pdf` 不覆盖 |

**这一步抓到的真问题**：该站用 `Content-Disposition: attachment;filename=%E5%85%AC…pdf`（百分号编码塞中文名，不是 RFC 5987 的 `filename*=`），1.0.4 原样落盘成 80 多字符的 `%E5%85%AC…` 乱码文件名；1.0.5 起 `percentDecode()` 解码，才得到可读的中文名。**判点补充：L3 除了"文件存在"，还要看文件名是否可读**——乱码名虽然字节正确，但人拿不到。

## T5 下载产物解析闭环

**目的**：验证"浏览器只是入口"——下载到的东西要能被后续工具消费。

| # | 步骤 | 期望 |
|---|---|---|
| 1 | 取 T4 落盘的 PDF | 文件存在 |
| 2 | 用 PDF/office 工具抽取首页文本 | 得到标题、文号、发布机关、生效日期 |
| 3 | 与 T4 页面信息比对 | 三处一致，不一致要说明（可能是附件与正文不匹配） |
| 4 | 产出 200 字摘要 + 引用出处（页码） | 摘要不含原文没有的条款 |

**判定**：字段 ≥4 且与原文可比对；摘要里的每条主张能在原文定位。**依赖 T4 的 L3**，T4 不过则本案例记「阻塞」。

### T5 实测（2026-11-20，插件 1.0.25）

| # | 动作 | 结果 |

## T6 结果翻页遍历 + 去重统计

| # | 步骤 | 期望 |
|---|---|---|
| 1 | 搜索结果页记录第 1 页条目指纹 | 例如 `标题+链接` 的 hash 集合 |

| 1 | 20 个 `art_<hash8>` | 国务院关于出境入境管理的规定 |

## T7 新窗口 / 内联预览行为探测

**目的**：把"插件没有新窗口策略"这件事变成一条有记录的结论，而不是线上才发现的意外。

| # | 步骤 | 期望（待定义） |
|---|---|---|
| 1 | 找 `target="_blank"` 的链接（1688 商品卡、规章附件常见） | 记录 href 与 target |

| 4 | 记录实际行为 + 期望行为 | 建议期望：同 webview 内导航，或返回 `blocked_new_window` 结构化错误 |

**设计后进展（2026-11-20）**：A15 已随 `1.0.11` 落地（TICKET-009）：点击 `target=_blank` 前改 `_self` → 同视图导航；`window.open` 补丁返回 `null` 并把 URL 挂在下一次动作的 `blockedNewWindow` 上。本案例在夹具页已跑通，真站（1688 商品卡 / 规章附件）复跑时按同一判据：**URL 变化 + 无新窗口 + 结果文案带注记**。

### T7 实测（2026-11-20，插件 1.0.25，规章附件真站）

| 路径 | 动作 | 实际行为 |
|---|---|---|
| 普通链接（target=_blank） | 1688 商品卡（T1） | 改 `_self` 后同视图导航到详情页 ✅ |

## T8 WAF 拦截 / 404 时换路

| # | 步骤 | 期望 |
|---|---|---|
| 1 | 打开一个可能被拦的地址（或人为构造 404 路径） | 页面出现拦截页/404 |
| 2 | agent 识别"这不是目标内容" | 能说出依据（标题/正文关键词/状态码文案） |
| 3 | **≤3 步内改变策略**：换站内搜索、换栏目、换镜像站 | 有明确的第二方案 |
| 4 | 若确实拿不到 | 汇报"被拦" + 已尝试的路径，**不死循环重试** |

**判定**：L2 能识别拦截页（不把"访问受限"当正文总结）；L3 换路成功或明确放弃；**重试同一 URL 超过 2 次 = 判失败**。

**预判**：部分通过。`plugin/inject/detect.js` 的验证检测应能覆盖显式验证码页，但**通用 WAF 挑战页/软 404 大概率不被识别**为 `needs_human`，会被当成普通页面硬解析——这正是本案例要暴露的。

### T8 实测（2026-11-20，插件 1.0.25）

四次尝试，三种失败形态，第 4 步换路成功：

| # | 路径 | 结果 | 依据（agent 能看到的） |
|---|---|---|---|
| 1 | 硬 404：`/zw/flfg/index-2026-nope.html` | 真 404 | `title = "404 Not Found"`、正文 `404 Not Found nginx`、零链接 |
| 2 | 站内搜索：首页 `#q` 输入「公平竞争审查条例实施办法」→ 点 `.search_btn input`；再 `submit:true` 回车 | **静默 no-op**（两次） | URL/标题均未变、无 blocked、无报错 → 判该站搜索在本面板不可用 |
| 3 | 换搜索引擎：Bing `site:samr.gov.cn …` | `ERR_CONNECTION_RESET (-101)` | 返回错误字符串；**并且面板被带到 `chrome-error://chromewebdata/`（title 空），上一页丢了** |
| 4 | 换栏目：回到 `/zw/flfg/index.html` | ✅ 可用 | 20 条列表 + layui 分页（T6 已实测） |

- **判级**：L2 ✅（三种失败都能说出依据，没把"404 Not Found nginx"当正文总结）；L3 ✅（3 步内换路，最终用栏目+分页拿到目标文档）；**同一 URL 重试未超过 2 次** ✅。
- **新问题（开单 TICKET-013）**：失败的 `browser_open` 把面板留在 `chrome-error://` 上，**上一页不可恢复**——这与 A1「打不开要在面板里说清楚」只差半步：错误说了，但现场丢了。
- **口径**：站内搜索没反应就换栏目/换站，别在无反应控件上连续第三次；附件用 `browser_download` 而不是点（T7）。
