## 3. 策略处置记录（案例要求的"哪步被拦、改走哪条路、还差什么"）

- **被拦 1**：`browser_eval` → `eval_disabled`。含义是"这台安装禁用页面执行"；**不是页面错误**，不要重试同一调用。
- **被拦 2**：`.dat` 下载 → `download_rejected`（`stage: policy`）。含义是"扩展名在黑名单里"，不是网络问题。
- **改走的路**：数据本来就在 HTML 表里 → `browser_snapshot` 的 a11y 树直接给出 30 行表格；这条路径**不执行脚本、不落可疑文件**，完全在策略内。
- **还差什么**：无。若当时数据只在 `.dat` 附件里且站点无 HTML 版，正确做法是如实报告"策略禁止该扩展名，需要运维改策略或人工下载"，而不是改名绕过。

## 5. 观察（不算失败，登记备查）

1. 改 profile 配置触发的重载有 **约 4–6 秒窗口**，期间工具短暂不可见（`unknown tool "browser_eval"`）。文档已提示"刚重载完等几秒"。
2. 同一份配置一次写入实测触发了**两轮**桥端口变化（8383 → 5033）：文件监听 + 插件各自重载一次。不影响结果，但会让"改一次配置 = 一次重启"的直觉出现偏差。
3. 该公告页的"公告概要"摘要金额为 `￥0.000000 万元`，正文是 `1027.000000(万元)`；摘要是站点字段问题（S1 也遇到同类），**以正文为准**。
