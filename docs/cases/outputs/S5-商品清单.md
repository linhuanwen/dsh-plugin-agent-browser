## 5. 两条偏离与发现

### 5.1 列表卡价格 ≠ 成交口径

搜索结果卡只给**起批价 + 促销标签**（如 `分享再减6元`、`首单减5元`、`元宝可抵1%`），详情页才会出现 SKU 价、阶梯价与划线价（#2 的 ¥150 / ¥144.50 / ¥142.50 / 划线 ¥175）。S5 判定里"活动价 / 券后价 / 原价写清"这条，**必须进详情页才做得到**，只看列表会误判。

### 5.2 登录态在应用重启后丢失（需回填已知限制）

本轮稍早（12:5x）登录后 `browser_eval` 读到 `{nickText:'毛民远之', cookieCount:29}`；13:07 用户重启 DSH 以加载工具栏改动；13:2x 再打开 1688 首页时右上是「立即登录」，搜索与详情均以未登录状态完成。=> **登录态跨"页面导航 / 插件重装"保持，但跨 DSH 进程重启不保持**（guest 的会话分区在重启后不保留 cookie）。发布说明与 README 的"登录态"表述需要按此收紧，避免用户以为重启后仍登录。

### 5.3 列表卡的 href 不是商品页

搜索结果卡的链接是 IM 咨询地址（`air.1688.com/...&offerId=...`），直接当详情打开会进聊天页；正确做法是从 href 里取 `offerId`，拼 `https://detail.1688.com/offer/<offerId>.html`。这条应写进复跑提示，避免下一个人把 IM 链接当商品链接。

## 6. 复跑提示

- M 步不必刻意"多次刷新"：1688 在未登录、连续搜索时自然弹「验证码拦截」；弹了就让真人做，不要尝试自动过。
- 真人完成后先 `browser_snapshot` 确认页面真的换了，再继续取数（避免在验证页上继续操作）。
- 详情页要等价格块渲染出来再读价；`browser_snapshot` 的树里价格可能是纯文本，直接 `browser_eval` 读 `innerText` 更快。
- 回访用详情 URL（`detail.1688.com/offer/<id>.html`），不要用列表卡 href。
