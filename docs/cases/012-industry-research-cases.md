# 行业调研验证方案（R1–R8）

> 状态：**已审核；R4 / R8 已执行**（2026-11-20，插件 1.0.29）。其余六案待跑。
> 目的：用七个真实行业/领域的上网调查场景，加上一条**素材落盘 → 正式报告**的交付链（R8），验证侧栏浏览器插件能否把**公开信息**取回来、核对上、讲清楚、交得出去——而不是只验证"能点能滚能截图"（那是 `docs/cases/010` 的事）和"能按流程跑完"（那是 `docs/cases/011` 的事）。
> 与既有案例集的分工：010 考**操作原语**，011 考**端到端任务**，012 考**信息质量**——数字对不对、版本是不是现行、两条来源冲不冲突。

---

## 0. 设计取向

调研类任务与"跑流程"任务的失败方式不同：流程跑通但结论错，比跑不通更有害。所以这八案一律按"**能不能交付一份可核对的调研结论**"判，而不是按"页面有没有动"判。

三条硬约束：

1. **只碰公开信息**。不登录、不提交表单、不下载需要账号的文档；遇到验证墙走 `needs_human` 交人，不绕过（D03/D20 的既有边界）。
2. **每个数字必须能落到"页面 + 原文/页码"**。落不了的就写"未取得"，不允许用相近页面顶替。
3. **至少两个来源**。单来源的结论标"单源未核"，不计入通过。

## 1. 八条案例总览

| # | 领域 | 真实调研问题（一句话） | 起点 | 主要考什么 | 站点风险（已实测/预判） |
|---|---|---|---|---|---|
| R1 | 医药·医保 | 某药是否进了最新医保目录、支付标准多少 | `https://www.nhsa.gov.cn/` ✅ 598 链接可读 | 公告 → 附件 PDF → 表格解析 | 附表常是 PDF/Excel 多附件；公告与附表版本可能不一致 |
| R2 | 金融·上市公司 | 某公司 2025 年报三个核心数字与同比 | `http://www.cninfo.com.cn/new/index` ✅ 189 KB DOM | 大 PDF 下载 + 解析 + 口径辨识 | 更正版覆盖原版；"净利润"与"归母净利润"易混 |
| R3 | 法律·合规 | 某条例是不是现行有效、最近一次修订是什么 | `https://www.gov.cn/zhengce/` ✅ 136 链接 | 版本沿革 + 时效判断 + 双源 | 旧版页面仍在线；征求意见稿冒充正式稿 |
| R4 ✅ | 政府采购 | 近 30 天某关键词的中标结果（供应商/金额） | `https://www.ccgp.gov.cn/` ✅ 279 链接、有搜索框 | 列表分页 + 去重 + 金额单位 | 同一项目多次公告（废标重招）；金额单位万元/元混用 |
| R5 | 科研文献 | GLP-1 减重近两年 3 篇文献的结论与 DOI | `https://pubmed.ncbi.nlm.nih.gov/` ✅ 单页 10 条、PMID 可抽 | 结构化抽取 + 结论一致性 | 撤稿标记；摘要≠全文结论 |
| R6 | 自然资源·土地 | 某市某区近一年成交的住宅用地（面积/价格/竞得人） | `https://www.landchina.com/` ✅ 可访问（38 链接，列表疑为 JS） | 动态表格 + 地区筛选 + 成交口径 | 列表大概率 JS 渲染；"出让公告"≠"成交公示" |
| R7 | 制造·供应链 | 某品类供应商的资质与产能（年限/规模/起订/交期） | `https://www.1688.com/` ✅ T1 已打底 | 详情页多模块抽取 + 反爬 | 滑块（D20 已补识别）；详情 tab 异步 |
| R8 ✅ | 交付链 | 把任一案的调研结果落成本地素材，再只用本地素材写一份正式报告 | 承接 R4 或 R1 的产物 | 素材落盘 + 三跳可追溯 + 报告生成 | 无新站点；考的是"本地文件能不能被消费" |


> 起点可访问性是 2026-11-20 在**当前面板**里逐个 `browser_open` 实测的，不是猜的。唯一实测打不开的是 **NMPA（`www.nmpa.gov.cn`）**：主页与数据查询页都返回**空壳**（`document.body.innerHTML.length === 0`，等 2.5 s 后仍为 0），所以医药领域改用国家医保局；NMPA 的空壳原因（UA/风控/纯 JS 门）记为待查，不影响本方案。

## 2. 共同规则

### 2.1 判级（沿用 011 的 L1–L4）

| 级 | 含义 |
|---|---|
| L1 | 页面到位（标题/URL 对得上） |
| L2 | 字段抽出来了（数字/名称/日期都在页面上找得到） |
| L3 | 结论可核对（每条主张有 URL/页码，跨源一致或不一致写清） |
| L4 | 结论可复跑（换个词条或换个月份，同一个流程还能出结果） |

通过线：R1/R2/R3/R4/R6 = **L3**；R5/R7 = **L3**（R5 的"结论一致性"允许写"证据不足"，只要说明白，仍算 L3）。

### 2.2 产物格式（每案一份）

```
docs/cases/outputs/R<N>-<领域>.md
  结论（3–5 句）
  要点表：主张 | 数值/文本 | 出处（URL + 页码/段落） | 核对状态（双源/单源/冲突）
  未取得项：要什么、卡在哪（登录/附件/动态表格/无此页）
  过程注记：走过的弯路、站点特性（给下次复跑用）
```

### 2.3 幻觉诱捕点（每案至少埋一个）

| 类型 | 例子 | 判失败的样子 |
|---|---|---|
| 过期版本 | 旧版条例页面仍在线 | 引用了被修订前的条款，且没提"已修订" |
| 站点当天日期 | 页面右上"2026年11月20日 星期五" | 当成发布日期（T5 已踩过） |
| 单位口径 | 万元/元、公顷/平方米、"归母"与"合并" | 数字对但量级错，或口径换了没说 |
| 相邻项目 | 同一关键词下另一项目的金额 | 张冠李戴，来源 URL 与结论不匹配 |
| 撤回/更正 | 年报更正版、公告更正、论文撤稿 | 引用了被更正前的数字 |

### 2.4 人工边界与预算

- 只有"验证墙/登录墙"可以交人（`needs_human`），其余人工介入即判失败。
- 每案预算：**≤ 15 步**、≤ 5 次 `browser_snapshot`（其余用 `browser_eval` 抽结构化数据，省 token）、≤ 2 次 `browser_download`。
- 时限：单案 10–15 分钟；超时按"未取得"记录，不算失败但要在产物里写明。

## 3. 逐案设计

### R1 医药·医保：某药是否进了最新目录

**真实问题**：以某款 PD-1 抑制剂为例，它是否被纳入最新版国家医保药品目录？协议期内支付标准是多少？

**步骤**

| # | 动作 | 判点 |
|---|---|---|
| 1 | `browser_open('https://www.nhsa.gov.cn/')` | 标题「国家医疗保障局」 |
| 2 | 进「政策法规」或「信息公开 → 医保目录」栏目 | 找到最近一次目录调整的公告列表 |
| 3 | 打开该公告 | 正文含"附表"下载链接（PDF/XLS） |
| 4 | `browser_download({url})` 取附表 | 返回 `{path,bytes,sha256}`，`mime` 是 pdf/xls |
| 5 | 解析附表，定位该药条目 | 药品名、剂型、支付标准、限定支付范围 |
| 6 | 与公告正文的品种数/口径交叉 | 附表条目数与正文"共纳入 N 个品种"一致或可解释 |

**判点**：药名与剂型都对上；支付标准带单位（元/片、元/支）；出处给到"公告标题 + 附表页码/行号"。
**诱捕点**：公告正文可能写"共 X 个"，附表实际是"协议期内谈判药品"另一个表——把两张表混为一谈就判失败。
**降级**：附表是扫描件 → 转用"政策解读"页的品种清单（仍有官方出处），但要在产物里注明"未能取得附表原文"。

### R2 金融：年报三个核心数字

**真实问题**：任选一家 A 股公司（例如制造业中盘股），取 2025 年年报的营业收入、归属于上市公司股东的净利润、经营活动产生的现金流量净额，以及三项的同比。

**步骤**

| # | 动作 | 判点 |
|---|---|---|
| 1 | `browser_open` 巨潮资讯网 | 标题「巨潮资讯网」 |
| 2 | 站内检索该公司 2025 年年度报告 | 列表里有「2025 年年度报告」与可能的「…（更正后）」 |
| 3 | **先看有没有更正版**，有则取最新 | 产物里必须写取的是哪一版、日期 |
| 4 | `browser_download` 下 PDF | 文件 > 1 MB、`%PDF` 头 |
| 5 | 解析「主要会计数据和财务指标」页 | 三个数字 + 单位（元）+ 同比（%） |
| 6 | 与交易所公告正文或 F10 页面交叉 | 数字一致，或差异可解释 |

**判点**：三项数字、单位、同比都对；口径写明"归母"；出处给到"年报标题 + 页码"。
**诱捕点**：把"净利润"当成"归属于上市公司股东的净利润"（两者不同，差在少数股东损益）；把"经营活动现金流量净额"写成"现金及现金等价物净增加额"。
**降级**：PDF 太大/解析失败 → 用「年报摘要」公告（同为官方披露），注明未用全文。

### R3 法律：这条条例现在还有效吗

**真实问题**：任选一部行政法规（例如《基金会管理条例》），回答：现行有效版本是哪一版？最近一次修订/修改是什么时间、依据什么决定？有没有被废止？

**步骤**

| # | 动作 | 判点 |
|---|---|---|
| 1 | `browser_open('https://www.gov.cn/zhengce/')` | 标题「政策_中国政府网」 |
| 2 | 检索条例名 | 结果里同时出现"现行版"与"修订决定""征求意见稿"时，能区分 |
| 3 | 打开现行版正文 | 文末或页首有"根据…修订"的沿革说明 |
| 4 | 找修订依据（国务院令号/日期） | 令号与日期成对出现 |
| 5 | 第二来源：司法部或国务院公报 | 两处日期/令号一致 |
| 6 | 给结论 | 「现行有效 / 已废止 / 部分条款失效」三选一，附依据 |

**判点**：结论是明确的三选一；修订令号与日期双源一致；引用的条款来自现行版而非旧版。
**诱捕点**：把「征求意见稿」当正式稿；把旧版页面的"发布日期"当"现行版本日期"；忽略"自 2026 年 X 月 X 日起施行"这类未来生效条款。
**降级**：政策库检索无结果（samr 的站内搜索 no-op 教训）→ 换 `site:` 检索或直接进部委站政策栏，产物里写明检索路径。

### R4 政府采购：近 30 天的中标结果

**真实问题**：以「服务器」为关键词，取最近 30 天的中标公告 3 条，抽采购人、中标供应商、中标金额、公告日期；判断有没有同一项目重复公告。

**步骤**

| # | 动作 | 判点 |
|---|---|---|
| 1 | `browser_open('https://www.ccgp.gov.cn/')` | 标题「中国政府采购网」，有搜索框 |
| 2 | 关键词检索 + 限定时间窗（页面若有时间筛选就用，没有就在抽取时过滤） | 结果列表出现、分页可见 |
| 3 | 抽前 2 页结构化数据（`browser_eval`） | 每条含标题/日期/链接/项目编号 |
| 4 | 去重（按项目编号或标题） | 重复条目数写清楚 |
| 5 | 取 3 条打开详情核对 | 4 个字段与列表一致 |
| 6 | 汇总 | 3 条 + 金额合计（注明单位） |

**判点**：3 条 × 4 字段；日期都在 30 天窗口内；金额单位明确；重复项目被识别。
**诱捕点**："采购公告"与"结果公告"混用（前者没有中标金额）；把预算金额当中标金额；万元/元混用。
**降级**：搜索无结果或分页失效 → 用栏目导航（信息公告 → 中标公告）再试一次，仍不行则记"站点检索不可用"。

### R5 科研：GLP-1 减重的三篇文献

**真实问题**：检索 GLP-1 受体激动剂用于肥胖治疗的文献，取 2024 年以来 3 篇，抽 PMID、期刊、年份、DOI 与主要结论；判断三篇结论是否一致。

**步骤**

| # | 动作 | 判点 |
|---|---|---|
| 1 | `browser_open('https://pubmed.ncbi.nlm.nih.gov/?term=GLP-1+obesity&filter=years.2024-2026')` | 单页 10 条 `article.full-docsum` |
| 2 | `browser_eval` 抽列表：PMID/标题/期刊/年份 | 10 条结构化数据（实测可抽） |
| 3 | 选 3 篇（含 1 篇综述、2 篇研究） | 类型标注正确 |
| 4 | 进详情页取 DOI 与摘要结论句 | DOI 形如 `10.xxxx/...`，摘要有原文句 |
| 5 | 检查撤稿/更正标记 | 有标记必须写 |
| 6 | 三篇结论一致性 | 一致/部分一致/冲突，附各自结论句 |

**判点**：3 个 PMID + 3 个 DOI；结论句来自摘要原文；一致性判断有依据。
**诱捕点**：把"相关"写成"证明"；综述的结论当原始研究结论；漏掉撤稿标记。
**降级**：部分文献无 DOI（较老/预印本）→ 记 PMID 与链接，说明"DOI 未取得"。

### R6 土地：某区近一年的成交地块

**真实问题**：取某市某区 2025 年成交的住宅用地 2 宗，抽宗地面积、成交价、竞得人、成交日期。

**步骤**

| # | 动作 | 判点 |
|---|---|---|
| 1 | `browser_open('https://www.landchina.com/')` | 标题「中国土地市场网」 |
| 2 | 进「土地供应」或「出让公告/成交公示」 | 找到可按地区筛选的入口 |
| 3 | 地区筛选 + 时间范围（若为 JS 表单，用 `browser_click({selector})` 或 `browser_eval` 驱动） | 列表出现目标区县的数据 |
| 4 | 抽表格行（`browser_eval` 读 `table` 或卡片） | 字段能对上表头 |
| 5 | 取 2 宗打开详情 | 面积/价格/竞得人/日期齐全 |
| 6 | 与省级平台或自然资源部公告交叉 | 至少一项能对上 |

**判点**：2 宗 × 4 字段；面积单位（公顷/平方米）写明；"成交公示"而非"出让公告"。
**诱捕点**：把"挂牌起始价"当"成交价"；把"出让面积"当"规划建筑面积"；跨区县张冠李戴。
**降级**：列表是纯 JS 且表格无 DOM 行 → 退到站内搜索或省级平台；仍不行记"该站列表不可抽"，这条本身也是有价值的结论。

### R7 制造·供应链：供应商资质与产能

**真实问题**：以「男士马丁靴」为例（承接 T1），选 2 家供应商，抽营业执照年限、工厂规模（面积/人数）、起订量、打样周期、是否支持定制。

**步骤**

| # | 动作 | 判点 |
|---|---|---|
| 1 | `browser_open('https://s.1688.com/selloffer/offer_search.htm?charset=utf8&keywords=男士马丁靴')` | 46 张卡（T1 实测）；注意 `charset=utf8` 不能丢 |
| 2 | `browser_eval` 抽卡片 → 选 2 家 | 卡片本身是 `<a class*="offerCard">` |
| 3 | 点进详情（卡片中心有 hover 工具条，必要时先 `browser_hover` 容器） | 落到 `detail.1688.com/offer/<id>.html` |
| 4 | 找「公司档案/工厂信息」模块 | 年限、面积、人数、起订、交期 |
| 5 | 交叉：店铺页的"诚信通年限/回头率" | 与详情页一致 |
| 6 | 汇总两家的差异 | 说明各自适合什么订单 |

**判点**：2 家 × 5 字段；每个字段注明来自哪个模块；不编造未展示的数字（1688 常见"面议"）。
**诱捕点**：把"店铺年限"当"工厂成立年限"；把"月销"当"产能"；把"起订量"与"起批量（阶梯）"混为一谈。
**降级**：详情页 tab 异步加载失败 → 用店铺页的公开档案；遇滑块 → `needs_human` 交人（D20 现在能识别）。

### R8 交付链：素材落盘 + 正式报告

**真实问题**：拿 R4（或 R1）已经取到的调研结果，先整理成**本地可复用的素材**（表格、截图、附件、清单），再**只用本地素材**写一份 2–3 页的正式报告。这一案不碰新站点，考的是"取回来的东西能不能沉淀成文件、文件能不能被消费、报告能不能倒查回原页面"。

**产物约定**（`docs/cases/outputs/R8-<主题>/`）

| 文件 | 内容 | 硬要求 |
|---|---|---|
| `assets/data.csv` | 结构化字段：项目/采购人/供应商/金额/日期/URL | UTF-8，首行表头，每条一行 |
| `assets/shot-list.png` | 列表页截图 | 宽 ≥ 768 px（插件 `browser_screenshot` 的固定输出宽度），能看到至少 3 条记录 |
| `assets/shot-detail.png` | 某条详情页截图 | 与 `data.csv` 的某行对应 |
| `assets/att-*.pdf` | 附件（若有） | 用 `browser_download` 取，记 sha256 |
| `assets/sources.json` | 每条素材 → URL + 抓取时间 + 文件 + 哈希 | 一条不落 |
| `report.docx` | 正式报告 | 2–3 页，1 表 1 图 |

**步骤**

| # | 动作 | 判点 |
|---|---|---|
| 1 | 读上一案产物，列出要落盘的字段清单 | 字段与报告结论一一对应 |
| 2 | `browser_eval` 补抽缺字段并写 `data.csv` | 行数 = 记录数，无空列 |
| 3 | `browser_snapshot` 出图，存 `shot-list.png` | 图里能读出至少 3 条记录 |
| 4 | 打开一条详情，截图 `shot-detail.png` | 与某一行同项目 |
| 5 | 有附件则 `browser_download`，算 sha256 | `sources.json` 记 size + sha256 |
| 6 | 写 `sources.json` | 每条素材都有 URL + 抓取时间 |
| 7 | 用 office 工具生成 `report.docx`（标题/摘要/方法/发现表/图/来源清单/不确定项） | 打开可见表格与图片 |
| 8 | 倒查：报告每个数字 → `data.csv` 行 → `sources.json` → URL | 三跳都通 |

**判点（三跳可追溯）**：报告里每个数字和每张图都要能追到素材文件的具体位置，素材要能追到 URL 与抓取时间。任何一跳断了判失败。

**诱捕点**：报告里出现素材中没有的数字；图片与数据不对应（A 项目的图配 B 项目的数据）；把"抓取时间"写成"发布时间"；合计与逐行相加不符。

**降级**：本案无附件 → 跳过第 5 步并在报告里写明"无附件"；docx 生成失败 → 退 `report.md`，但 `data.csv` 与 `sources.json` 必须仍在。

**预算**：≤ 10 步、≤ 2 次截图、≤ 1 次下载、报告 ≤ 3 页。
