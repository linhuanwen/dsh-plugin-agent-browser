## 0. 为什么功能级不够，还要实操级

功能级案例的天然缺陷：**它可以在"什么都顺利"的环境里通过**。改一个配置、调一个工具、断言一个 code，全绿——但只要真实工作里出现"面板被最小化""站点临时抽风""组织禁了 eval""会话被人拉黑"，功能级测试根本碰不到这些组合。

所以本集给每条案例加了一条硬规则：

> **每案必须包含至少一个"人为制造或等待的障碍步"**（M 步，Marked），并且该步必须真的发生（记录证据）。障碍没发生，该案记为"条件未触发"，**不算通过**，改天重跑。

障碍来源三选一：真站点不稳定（不可控，等它发生）、人为改配置/改环境（可控，推荐）、人为给错输入（可控）。

| 障碍类型 | 例子 |
|---|---|
| 失败导航 | 先打一个已失效的旧地址；或构造 `:8080` 端口敲错 |
| 策略拦截 | 临时把组织策略开成"禁 eval / 禁 .dat / 只许别的会话" |
| 验证墙 | 真实站点的滑块/验证码（1688 等） |
| 环境异常 | 插件刚重载完 8 s 内调用；面板最小化后截图 |
| 会话隔离 | allowlist 把当前会话拉黑，换会话复验 |

## 2. 共同规则

### 2.1 判级（沿用 011/012）

| 级 | 含义 |
|---|---|
| L1 | 页面到位 |
| L2 | 产物出来（文件/清单/截图，字段对得上） |
| L3 | 产物可核对（每条有 URL/页码/文件哈希；障碍处的处置有记录且正确） |
| L4 | 换词条/换月/换会话，同一流程还能出结果 |

### 2.2 障碍记录（本集的核心证据）

每个 M 步必须留下记录，写进产物 `notes/` 或案例实测小节：

| 字段 | 内容 |
|---|---|
| 障碍是什么 | 一句人话 + 触发方式 |
| Agent 看到什么 | 工具返回的原文（code / 页面标题 / 截图） |
| Agent 做了什么 | 下一步动作（换路/交人/放弃/重试） |
| 是否重复瞎试 | 同一动作重复次数（>2 次判失败，见 T8 口径） |
| 结果 | 任务继续 / 降级交付 / 明确放弃并说明原因 |

### 2.3 人工边界

- 允许人参与：验证墙、GUI 视觉确认、取消按钮。
- 不允许：搭手帮 Agent 点页面、替它总结内容、替它重试。
- 人工操作必须写"人做了什么 + 耗时"，供下次判断是否环境差异。

### 2.4 预算

- 每案 ≤ 20 步，≤ 8 次 `browser_snapshot`（其余用 `browser_eval` 抽结构化数据），≤ 3 次 `browser_download`。
- 单案 15–20 分钟；含人工的按 25 分钟估。
- 改配置的案例（S3/S4）跑完必须恢复 profile patch 到 2,071 字符 / 54 行 / UTF-8 / 末尾换行。

## 3. 逐案设计

### S1 政府采购：近 30 天某关键词的中标清单

> 用户原话："帮我查下最近一个月「数据中心」相关的中标结果，要供应商、金额、日期和公告链接，至少五条。"

**为什么这条会撞硬化能力**：政采站点（`ccgp.gov.cn`）已经实测可读（R4 已跑通 167 条），但真实工作里大概率遇到三件事——旧入口/栏目路径变了（失败导航）、同一项目多次公告（去重）、附件是表格（下载 + 落盘）。这正好把 013（回退）、027（换路）、T6（翻页去重）、T4（下载）串起来。

| # | 步骤 | 期望 |
|---|---|---|
| 1 | 从 R4 记录的入口开页（`https://www.ccgp.gov.cn/`），先确认列表可达 | 标题/列表正常 |
| **M** | **人为打一个旧入口**（如 `http://www.ccgp.gov.cn/cggg/zygg/index_2.htm` 之类已变路径，或 `https://www.ccgp.gov.cn:8080/`） | 返回 `navigation_failed: nav_*`；**面板回退到上一步的列表页**；错误含原始 URL |
| 2 | 记录 M 步的 code 与 stage；确认 `browser_snapshot` 仍能读到列表（现场没丢） | 有 stage、有上一页 |
| 3 | 用站内搜索/栏目入口找「数据中心」，翻 2 页取候选 | ≥ 8 条原始候选 |
| 4 | 按"项目编号 + 公告类型"去重，取 ≥ 5 条目标 | 去重后 ≥ 5 条，含废标重招的排除说明 |
| 5 | 落盘一个清单文件（`research/S1-中标清单.md`：标题/供应商/金额/日期/公告 URL） | ≥ 5 行，每行 URL 可回访 |
| 6 | 抽查 2 条回访，核对金额单位（元/万元） | 单位一致或有换算说明 |

**产物判定**：L1 列表可达；L2 清单 ≥ 5 行且字段齐；L3 每条有可回访 URL、单位口径写清、M 步处置正确（没在失败入口上重试 >2 次）；L4 换关键词重跑仍有结果。

**降级路径**：列表改版 → 换栏目入口；搜索无反应 → 换关键词/换地区；附件需下载 → `browser_download`（见 T4 口径）。

**判负**：M 步失败后没有回退（面板停在 `chrome-error://`）；同一失效地址重试 >2 次；清单里出现页面上没有的金额（幻觉）；把"废标重招"当成两条独立项目。

**成本**：8–10 步 / 6–8 分钟 / 稳定性中（站点稳定，列表可能改版）。

### S2 会议材料：给当前页面截图并配图注

> 用户原话："把刚才那个统计页面截一张图，配一句话说明，放进会议材料里。"

**为什么这条会撞硬化能力**：截图是唯一同时踩 023（卡片可见）、028（隐藏面板/首次绘制）、V10（静默失败）的能力。真实开会的场景恰恰是"面板在后台、窗口被别的应用挡住"——这正是 `capturePage` 不产帧的条件。

| # | 步骤 | 期望 |
|---|---|---|
| 1 | 打开目标页（如百度地图某城市视图，或 gov 统计页），确认可读 | 标题/内容对 |
| 2 | `browser_screenshot({mode: 'viewport'})` | 落盘 PNG；对话里出现**缩略图卡片**（不是一行路径） |
| 3 | 写图注（一句话：这是什么、日期、数据口径） | 图注与截图一致，不编造数字 |
| **M** | **把面板切到后台/最小化，再截一次** | 明确文案 `the browser panel is hidden right now …`；**不是** `UnknownVizError`；不产生 0 字节文件 |
| 4 | 恢复面板到前台，重试截图 | 成功；文件可打开 |
| 5 | 人工确认三件事：缩略图能看清、尺寸/大小与文件一致、点开是原图 | 🖐 记录确认结果 |

**产物判定**：L1 截图落盘；L2 缩略图在对话里可见 + 图注准确；L3 隐藏面板时给出可执行提示而不是内部错误，恢复后一次成功。

**判负**：只出路径不出图；隐藏时抛 `UnknownVizError`；图注里的数字页面上看不到；截的是空白页却报成功（V10 的老坑）。

**成本**：5 步 + 1 次人工 / 5 分钟 / 稳定性高。

### S3 受限策略下的取数：禁 eval、禁 .dat 也要把表拿回来

> 用户原话："公司安全规定了不许网页执行脚本，也不许往工作区下 .dat；但你得帮我从那个页面把表拿回来。"

**为什么这条会撞硬化能力**：这是 TICKET-024 的真实用途——策略收紧后，任务不能就此报废。功能级验证只断言"被拒且 code 正确"，实操级要回答"**拒绝之后怎么办**"。

| # | 步骤 | 期望 |
|---|---|---|
| **M** | profile patch 设 `evalEnabled: false` + `downloads.extraBlockedExtensions: [dat]`，等重载 | `fiberPhase: active`，工具仍在 |
| 1 | 试 `browser_eval` 抽表 | `eval_disabled: …`（明确说这是安装选项，不是页面问题） |
| 2 | 改走 `browser_snapshot({maxChars: 20000})` 或 `browser_click` + 复制路径，取表格数据 | 拿到 ≥ 5 行结构化数据 |
| 3 | 若表只在 `.dat` 附件里：试 `browser_download` | `download_rejected`，文案说明扩展名被策略禁止 |
| 4 | 找替代路径：网页版表格 / CSV / 在线预览 / 找同站 HTML 版 | 有明确的第二方案（或如实写"拿不到，原因×"） |
| 5 | 交付：数据文件 + 一段"策略处置记录"（哪步被拦、改走哪条路、还差什么） | 产物齐 + 不绕过策略 |
| 6 | 恢复 profile 配置，复验 eval 与下载恢复 | 全部回到默认 |

**产物判定**：L1 策略生效；L2 被拦时有 code + 人话；L3 有替代产物或明确的"不可得"说明，且**没有绕过策略**（没偷用 eval、没改名骗过黑名单）。

**判负**：被拦后直接说"做不了"；偷偷用 eval；把扩展名改成 `.txt` 骗过策略；没恢复配置。

**成本**：7 步（含 2 次重载）/ 10 分钟 / 稳定性中。

### S4 会话隔离：批量会话不许碰浏览器，人工会话不受影响

> 用户原话："这个批量任务跑在自动化会话里，规定它不能开浏览器；我自己这个会话要正常用。"

**为什么这条会撞硬化能力**：`sessions.allowlist` 是唯一"按会话"生效的策略。真实工作里常常是"人机并存"：人要用浏览器查证，批量任务不该抢面板。

| # | 步骤 | 期望 |
|---|---|---|
| **M** | 把 allowlist 设成 `[只写人工会话之外的会话 id]`，或反过来只放行人工会话 | 重载后规则生效 |
| 1 | 在人工会话里 `browser_open` | 正常（未被误伤） |
| 2 | 在被拉黑的会话里调 `browser_*`（可用新会话或子 agent 复现） | 全部 `session_not_allowed`，且**不产生桥流量**（面板状态不变） |
| 3 | 观察桥 `/health` 计数：被拒调用前后是否增加 | 不增加（guard 在工具体之前） |
| 4 | 恢复默认（空名单） | 全部会话恢复可用 |
| 5 | 双实例隔离：本地起第二个 Bridge，确认两个实例端口不同、令牌互不通过 | 互不影响 |

**产物判定**：L1 规则生效；L2 两个会话表现不同且各自的 code 正确；L3 被拒调用零桥流量、恢复后无残留。

**判负**：allowlist 生效但人工会话也被拒（规则做反了还"自我感觉良好"更糟）；被拒调用仍打到面板；恢复后仍有会话被拦。

**成本**：6 步 / 8 分钟 / 稳定性高（需两个会话，可用子 agent）。

### S5 验证墙交接：人过完之后把活干完

> 用户原话："1688 上帮我找三款男士马丁靴，价格和店铺都要，别自己过验证码——弹了我来看。"

**为什么这条会撞硬化能力**：真实站点弹验证是常态。硬化后要考的不是"能不能识别墙"（V8/H8 已考），而是**交接之后状态能不能清掉、任务能不能续上**——这条从未跑过。

| # | 步骤 | 期望 |
|---|---|---|
| 1 | 打开 1688 搜索"男士马丁靴" | 若首屏正常，先取 1 条做基线 |
| **M** | 触发验证（多次刷新/直接搜索关键词，或落到带滑块的搜索页） | 工具返回 `needs_human`；**不往验证页里乱点**；面板提示人处理 |
| 2 | 记录：返回的 code、提示文案、面板状态（页面停在验证页） | 有 code、有人话、页面未被破坏 |
| 3 | 🖐 人工在面板完成验证（人做什么、耗时） | 人完成，页面进入正常结果 |
| 4 | 再次 `browser_snapshot` 与 `browser_open` | 不再返回 `needs_human`，状态已清 |
| 5 | 继续取 3 款商品：标题/价格/店铺 | 3 行，价格档位写清（活动价/券后价/原价） |
| 6 | 回访 1 个商品链接确认仍在 | 可回访 |

**产物判定**：L1 墙被识别；L2 交接文案清楚、页面没被弄坏；L3 人完成后任务续上并交付 3 条可回访数据；L4 换个词条仍能走同一流程。

**降级路径**：验证反复弹 → 换搜索词/换分类入口；价格抽不到 → 写"未取得"而不是编。

**判负**：把验证页当正常页解析；人完成后工具仍返回 `needs_human`/`taken_over`；编造价格（T1 已定的三档口径）；同一控件连点 >2 次。

**成本**：6 步 + 人工 / 10–15 分钟 / 稳定性低（站点反爬）。

### S6 故障接手：同事遇到三种报错，能不能自助

> 用户原话："我按文档把插件给了同事，他那边报错了，你看他描述能不能自己解决，别每次都来找我。"

**为什么这条会撞硬化能力**：13 个稳定 code 和故障排查文档是 020/023/025 的产物，但从没考过"**拿着 code 能不能自助恢复**"。这条用脚本人为制造三种故障，要求 Agent 只依据 code + 用户文档处置。

| # | 步骤 | 期望 |
|---|---|---|
| **M1** | 制造"面板未开"：关掉面板页签后调 `browser_open` | `panel_not_open`，文案含"打开侧栏浏览器页签" |
| **M2** | 制造"刚重载"：`set_plugin enable=false→true` 后 3 s 内调用 | `bridge_timeout`（或 8 s 内自恢复）；文案含"刚重载/等几秒"语义 |
| **M3** | 制造"写错域名"：`browser_open https://no-such-host.invalid/` | `navigation_failed: nav_dns`，回退到上一页 |
| 1 | 只看返回文本 + 用户 README 的故障排查表，给出处置动作 | 三个 code → 三个不同处置（开页签 / 等待重试 / 换地址） |
| 2 | 按处置动作执行，验证恢复 | 三个都恢复 |
| 3 | 记录"处置表"：code → 症状 → 动作 → 结果 | 3 行，动作与文档一致 |
| 4 | 反向：故意给一个**不存在的 code**（如 `panel_frozen`）问文档 | 文档里查不到 → 明确说"未知 code，按通用步骤排查"，不编造解释 |

**产物判定**：L1 三个故障都能触发；L2 三个 code 与文档处置一一对应；L3 按文档恢复成功，且反向用例不瞎编。

**判负**：把所有错误都当"重试"（同一动作 >2 次）；对未知 code 编造原因；恢复后不记录。

**成本**：7 步（含 1 次重载）/ 8 分钟 / 稳定性高（故障可控）。

### 7.2 执行中发现（供后续修/登记）

1. **S1 分类口径**：`ERR_SSL_PROTOCOL_ERROR` 被判成 `nav_cert`（文案"the certificate was rejected"），实际是协议/端口不匹配。属 `plugin/navigation.js` 规则偏粗，建议后续把 `ERR_SSL_PROTOCOL_ERROR` 单列或归 `nav_unknown`。

3. **S3 站点口径**：公告摘要金额字段可能为 0（正文有值），实操以正文为准 —— 与 S1 同一发现。
4. **S4 名单匹配**：精确字符串匹配，写错一个字符即拦截；清除后 guard 放行，子代理的错误退化为 `panel_not_open`（环境语义）。

### 7.4 S2 隐藏面板三态 — ✅ 全部实测（2026-11-22，1.4.8，🖐 人工最小化）

S2 的 M 步要求"面板不在前台时截图，必须给出可读错误而不是坏图/超时"。实测先踩了两次"隐藏条件触发不了"，才找到真正能触发的方式：

| 隐藏方式 | `document.visibilityState` | 截图结果 |
|---|---|---|
| 收起整条右侧边栏 | `visible`（695×863 不变） | 成功（46.0 KB）——宿主只是把面板移出可视区，webview 仍在绘制 |
| 切换侧栏页签（浏览器 → 工具） | `visible`（仅 `hasFocus:false`） | 成功（46.0 KB） |
| **最小化窗口** | **`hidden`** | `Error: screenshot failed at command: the browser panel is hidden right now (its pane or the app window is not visible), so the page is not being rendered and cannot be captured. Bring the panel into view and retry.` |
| 恢复窗口、但面板页签不在前台 | `visible` | `the browser panel produced no picture: the page had not painted yet, or the panel is not visible on screen. Bring the DSH window and the browser panel into view, then retry the screenshot.` |
| 恢复窗口 + 点回「浏览器」页签 | `visible` | `Saved screenshots/shot-20261122-162133.png (panel size, 46.0 KB)` |

**结论**：三种状态对应三种正确行为——隐藏给 `hidden` 文案、可见未绘制给"produced no picture"文案、正常给文件。`document.visibilityState` 是可靠判别依据；"收起侧栏/切页签"不算隐藏（这是宿主实现细节，写进复跑注意，免得下次误判）。

**复跑提示**：只有**最小化**能稳定造出 `hidden`；如果需要复现"可见但未绘制"，恢复窗口后立刻截图即可（第一批重试会失败，第二次通常成功）。
